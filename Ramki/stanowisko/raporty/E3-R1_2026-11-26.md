# E3-R1 - przelacznik "ramki wylaczone" + galaz zbiorcza na pokaz 28.11 (zlecenie r1, 26.11.2026)

Galaz `e3/r1` = galaz zbiorcza: `origin/e3/u1b` (f170218; zawiera U1a i U1b) + scalenie `origin/e3/i1` (2640471) w commicie

## Zakres

W sobote 28.11 wlasciciel instaluje program na laptopie ze skanerem BEZ elektroniki ramek (decyzja 23.11: "instalator: ramki
domyslnie wylaczone"). Do E3-R1 program nie mial przelacznika - pokazalby "ramka nieobecna" jako usterke (KONIEC_i1, "Co zostalo"
p. 1). Teraz:

- klucz `[ramki] wlaczone` (bool, opcjonalny). Brak klucza = `true` - zachowanie sprzed E3-R1 (stare instalacje i aktualizacja bez
  zmian, bez kodu 7);
- `false`: program nie tworzy klientow ramek i nie probuje sie z nimi laczyc; pasek stanu pokazuje neutralne "Ramki: wylaczone"
  (zwykly kolor tekstu, kropka bez barwy, bez "Test LED" / "Przejmij ramke", podpowiedz: jak wlaczyc); bez komunikatow "ramka
  poranna nie jest podlaczona" / "ramka wieczorna nie odpowiada" w strefie pytan i na liscie bledow programu, bez ostrzezen w logu
  (jeden wpis INFO); samokontrola: oba wiersze ramek OK "ramki wylaczone w ustawieniach", bez proby polaczenia (takze bez
  `--bez-sieci`); reszta programu bez zmian (rano rozkladanie wedlug ekranu - jak bez ramki);
- instalator okienkowy przy NOWEJ instalacji wpisuje `wlaczone = false` (mechanizm byl juz w E3-I1 i czekal, az program pozna klucz
  - kod instalatora bez zmian); przy aktualizacji `ustawienia.toml` zostaje bajt w bajt;
- `ustawienia.przyklad.toml`: `wlaczone = true` z komentarzem (co znaczy false, ze instalator wpisuje false, jak wlaczyc ramki);
- instrukcja instalacji, punkt 9: jak wlaczyc ramki.

## Odstepstwa

- `stanowisko/kontroler_api.py` nie byl wymieniony z nazwy. Zmieniony jako "miejsce startu polaczenia z ramka" (`podlacz_ramki` -
  tam klienci sa uruchamiani) i dlatego, ze komunikat "Ramka poranna nie jest podlaczona" (trwaly, strefa pytan) budowal kontroler
  takze w programie bez ramek - bez tej zmiany kryterium 4 rano nie bylo do spelnienia. Zmiana addytywna: pole
  `StanRamek.wylaczone` (domyslnie False), metoda `wylacz_ramki()`, jeden warunek przy komunikacie `ramka_niedostepna`.
- Kod instalatora (`instalacja/`) bez zmian: zapis klucza przy nowej instalacji byl gotowy od E3-I1 (`--ramki-wylaczone`, pytanie
  programu o `klucze_ramek`) - zmienione tylko testy i opis.
- `main --atrapa` czyta teraz `[ramki] wlaczone` z pliku ustawien (jesli plik jest i jest poprawny; inaczej atrapa jak dotad). Bez
  tego proba startu i zrzuty z instalacji nie pokazalyby paska "Ramki: wylaczone".

- "Wiersz neutralny" samokontroli = poziom OK z opisem "ramki wylaczone w ustawieniach" (umowa formatu samokontroli z instalatorem
  zna tylko OK / OSTRZEZENIE / BLAD - nowy poziom zmienilby styk). Dwa wiersze (kody `ramka_wieczorna`, `ramka_poranna`) jak dotad.
- Wzor `ustawienia.przyklad.toml` ma `wlaczone = true` (= brak klucza = stare zachowanie, zgodnosc z `DOMYSLNE_NOWYCH`, test).
  `false` wpisuje tylko instalator przy nowej instalacji z okna.
- Rano przy wylaczonych ramkach `StanRano.ramka` = False (jak bez ramki) - ekran poranny rozklada wedlug ekranu, bez komunikatu.
- Program bez ramek NIE z woli ustawien (atrapa, testy, `ramki=False`) - jak dotad: pole ramek ukryte, rano komunikat
  `ramka_niedostepna` (test `test_okno_bez_ramek_bez_przelacznika_jak_dotad`).
- Przelacznik czytany przy starcie programu; zmiana w pliku = ponowne uruchomienie (podpowiedz paska i instrukcja to mowia).
